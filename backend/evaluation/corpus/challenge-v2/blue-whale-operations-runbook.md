# 蓝鲸运行手册

## 存储职责

蓝鲸把上传的原始文件保存在 MinIO；知识库元数据、文档状态、持久化入库任务、文本 Chunk 和向量保存在 PostgreSQL，其中向量检索由 pgvector 完成。

Redis 只承担最近消息缓存、事件协调和 Celery Broker。Redis 不是 RAG 事实来源，因此清空 Redis 不会删除原始文件、文档状态、Chunk 或向量。

## 入库与恢复

上传成功后，API 先在 PostgreSQL 创建状态为 PENDING 的持久化任务，再尝试投递 Celery 消息。投递失败时不删除任务；恢复扫描器会在协调服务恢复后重新投递超过租约时间的任务。

Worker 解析文件并生成全部 Embedding 后，在一个 PostgreSQL 事务中替换旧 Chunk，同时把文档和任务更新为终态。事务失败会整体回滚，不能留下部分新 Chunk 和已经成功的文档状态。

同一知识库通过文件 SHA-256 判断重复上传，重复文件返回 409。任务使用幂等键和原子领取避免重复执行；重复投递不会生成两套 Chunk。

## 失败处理

加密 PDF、扫描后没有可提取文字的 PDF、空 TXT 和无法解码的 Markdown 都应进入明确的失败状态。用户修复文件后可以重新上传；对于可重试的基础设施错误，可以通过文档重试接口创建新的执行尝试。

运维排查顺序是先看 PostgreSQL 中的文档与任务状态，再看 Worker 结构化日志，最后检查 Redis 和 MinIO 连通性。不能只根据浏览器是否收到 200 判断入库成功。
