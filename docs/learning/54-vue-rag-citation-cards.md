# Vue RAG 引用卡片

## 1. 本模块解决什么问题

上一模块已经把实时 `sources` 和历史 `citations` 都保存到了助手消息对象，但页面只显示回答正文。
用户无法核对答案来自哪个文件、哪一页，也就还不能称为“可追溯问答”。

本模块补齐最后一段展示链路：

```text
后端历史 citations / SSE sources
→ Pinia message.citations
→ ConversationDetailView
→ MessageCitationList
→ 文件、页码、标题路径和原文片段
```

## 2. 为什么实时和历史只需要一个组件

实时来源和历史引用虽然来自不同接口，但上一模块已经抽取了共同类型：

```text
MessageSource
├─ 文件和知识库名称
├─ 页码与标题路径
├─ 原文快照
├─ source_order
└─ 当前仍然有效的可选外键
```

SSE 收到来源后，Store 将它们挂到正在生成的助手消息；页面刷新后，历史接口又会把数据库中的引用
快照放回同一个 `message.citations`。因此展示组件只依赖 `MessageSource[]`，不关心数据来自网络流还是
历史查询。

这是一种重要的前端分层：

- API 层负责校验网络协议。
- Store 负责保存和合并状态。
- 页面负责决定引用放在哪里。
- 引用组件负责怎样展示。

## 3. 页面接入规则

会话页面只在以下条件同时满足时渲染组件：

```text
message.role === "assistant"
并且
message.citations.length > 0
```

这样可以保证：

- 用户消息和工具消息不会误显示来源。
- 普通聊天没有 RAG 来源时不会出现空标题或空卡片。
- 无证据拒答的 `sources([])` 仍是一条正常助手消息，但不会制造不存在的引用。

## 4. 为什么组件内部还要排序

后端已经保证 `source_order` 连续有序，但展示组件仍然通过副本排序：

```ts
[...props.sources].sort(...)
```

这里的重点不是怀疑后端，而是防止组件直接修改 `props.sources`。JavaScript 的 `sort()` 会原地修改
数组，如果直接排序 Prop，就可能同时改变 Pinia 中的消息状态。复制后排序让组件保持“只读展示”。

## 5. 页码怎样显示

页面规则是：

| 数据 | 展示 |
| --- | --- |
| `page_start = null` | 页码未知 |
| 起止页相同 | 第 2 页 |
| 起止页不同 | 第 3–5 页 |
| `page_end = null` | 使用起始页，不猜测额外页码 |

Markdown 和 TXT 没有天然物理页码，所以显示“页码未知”是诚实表达，而不是数据错误。PDF Parser 能保留
页码时，用户才可以准确回到原文页面。

## 6. 什么是“历史快照”

回答成功时，系统已经把文件名、页码和原文片段复制到 `message_citations`。以后用户删除知识库或
文档，外键会变成 `null`，但旧回答仍应能说明当时依据了什么。

组件在 `document_id === null` 时显示“历史快照”：

```text
有 document_id → 当前来源仍存在
无 document_id → 只展示回答生成时保存的审计快照
```

本步骤没有文档详情路由，因此不渲染虚假的链接。以后增加文档详情或下载接口时，也只能在外键仍有效
且通过所有权检查后提供跳转。

## 7. 为什么不显示“置信度 91%”

`score` 是检索阶段的向量相似度，不是以下任何一个概率：

- 答案正确概率；
- 文档可信概率；
- 模型置信概率。

把 `0.91` 直接显示为“91% 置信度”会误导用户。第一版卡片优先展示可核查证据，分数保留在协议中供
调试和评测使用。以后如果面向管理员增加检索调试面板，可以明确写作“向量相似度”，不能称为答案
置信度。

## 8. 长原文怎样展开

每条引用独立保存展开状态：

```text
Set<number>
└─ 已展开的 source_order
```

默认最多显示 140 个字符，长文本出现“展开原文”按钮，展开后按钮变成“收起原文”。修改 Set 时创建
一个新 Set 并重新赋值，使 Vue 能稳定观察状态变化。

按钮还带有 `aria-expanded`：

- `false` 表示内容处于折叠状态；
- `true` 表示内容已经展开。

这既方便屏幕阅读器理解，也能让测试直接验证真实交互状态。

## 10. 测试保护了什么

组件测试覆盖：

- 输入顺序混乱时仍按 `[S1]`、`[S2]` 展示。
- 页码范围、知识库和标题路径正确显示。
- 文档删除后显示历史快照，未知页码不被猜测。
- 长原文默认截短，可以展开和收起。
- 空来源不产生空卡片。

页面测试覆盖：

- 历史助手消息的 `citations` 能进入真实引用组件。
- 文件名和单页页码出现在消息正文下方。

## 11. 本模块尚未做什么

- 还没有知识库管理页面。
- 还不能从 Vue 创建知识库、上传文档或查看入库状态。
- 还没有会话知识库选择器。
- 引用卡片暂时不能打开或下载原文档。
- 还没有检查回答正文中的 `[Sx]` 是否都能对应真实来源。
- 还没有建立 RAG 评测集。

下一小步进入 **RAG-6A：Vue 知识库 API 与状态层**。先让前端能够读取、创建、更新和删除用户自己的
知识库，并为后续上传页面建立清楚的数据状态，不会马上把所有界面堆在一起。

## 12. 常见错误

| 现象 | 原因与处理 |
| --- | --- |
| 实时能看到引用，刷新后消失 | 后端没有持久化或历史接口没有返回 citations |
| 刷新后有引用，生成时没有 | SSE sources 没写入对应助手消息 |
| `sort()` 后 Store 顺序也变了 | 直接对 Prop 数组原地排序，应先复制 |
| TXT 显示了猜测页码 | 未知页码必须明确显示未知 |
| 删除文档后整个旧引用消失 | 只依赖活外键，没有保存引用快照 |
| 相似度显示为答案置信度 | 混淆检索分数和回答正确概率 |
| 每条消息都显示“参考来源（0）” | 页面没有检查 citations 是否为空 |

## 13. 面试表达

> 我把实时 SSE sources 和历史 citations 统一成 MessageSource，Pinia 负责状态合并，Vue 页面只决定
> 引用挂在哪条助手消息下，可复用组件负责排序和展示。引用卡片展示文件、页码、标题路径和生成时的
> 原文快照；文档删除后外键虽然为空，旧回答仍能审计并明确标记为历史快照。我没有把向量相似度包装
> 成答案置信度，避免误导用户。组件还支持长片段展开，并用单元测试和页面接入测试分别保护展示逻辑
> 与真实调用链。

## 14. 小练习（约 15–20 分钟）

给引用组件补一个“只有 `page_end` 为空、`page_start` 为 7”的测试：

1. 复制一条测试来源。
2. 设置 `page_start: 7`、`page_end: null`。
3. 挂载组件。
4. 断言显示“第 7 页”。
5. 断言没有出现页码范围符号 `–`。
6. 运行：`npm run test:run -- MessageCitationList.test.ts`。

答案要点：`page_end` 缺失只代表没有结束页信息，不能把它当作第 0 页，也不能猜测跨页范围。
